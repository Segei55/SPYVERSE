# Руководство по сетевому подключению и голосовой связи SPYVERSE

SPYVERSE поддерживает гибкую сетевую модель без обязательного внешнего сервера разработчика: игрок может поднять сервер на своём ПК или использовать встроенный веб-сервер.

---

## 1. Способы подключения друзей

### Вариант A: Локальная сеть (LAN / Wi-Fi)
1. Компьютер хоста и компьютеры/смартфоны друзей подключены к одному роутеру (по кабелю или Wi-Fi).
2. Хост запускает сервер или нажимает «Создать комнату».
3. В окне «Свой сервер & Сетевая игра» хост смотрит свой локальный IP-адрес (например, `192.168.1.15`).
4. Друзья открывают игру, в «Настройках» указывают адрес сервера `http://192.168.1.15:3000` (или `3001` для standalone), после чего вводят 6-значный код комнаты в меню «Войти по коду».

### Вариант B: Виртуальная сеть VPN (Hamachi / Radmin VPN)
1. Хост и друзья создают сеть в LogMeIn Hamachi или Radmin VPN и входят в неё.
2. Хост копирует свой IP-адрес из окна Hamachi (начинается на `25.x.x.x`) или Radmin (начинается на `26.x.x.x`).
3. Друзья вводят этот IP с портом сервера в поле «Адрес сетевого сервера» в Настройках SPYVERSE.
4. Вводят код комнаты и подключаются без необходимости проброса портов на роутере.

### Вариант C: Прямое подключение через Интернет (Port Forwarding)
1. Хост открывает порт `3000` или `3001` (TCP) в настройках своего роутера (Port Forwarding / Виртуальный сервер).
2. Хост сообщает друзьям свой публичный IP (например, `http://93.184.216.34:3000`).

## 2. Голосовая связь WebRTC

- **Сигнализация:** проходит через Socket.IO (события `voice_signal`). Клиенты обмениваются Offer, Answer и ICE-кандидатами.
- **STUN серверы по умолчанию:** используются публичные серверы Google:
  - `stun:stun.l.google.com:19302`
  - `stun:stun1.l.google.com:19302`
- **TURN для сложных сетей:** STUN не может установить соединение за некоторыми NAT, корпоративными брандмауэрами и мобильными сетями. Для таких игроков настройте TURN-сервер (например, coturn) на сервере SPYVERSE через переменную окружения `WEBRTC_ICE_SERVERS`. Значение — JSON-массив серверов; TURN-конфигурация добавится к STUN по умолчанию:

  ```json
  [{"urls":"turn:turn.example.com:3478","username":"ВРЕМЕННЫЙ_ЛОГИН","credential":"ВРЕМЕННЫЙ_ПАРОЛЬ"}]
  ```

  В Windows PowerShell перед запуском сервера:

  ```powershell
  $env:WEBRTC_ICE_SERVERS='[{"urls":"turn:turn.example.com:3478","username":"ВРЕМЕННЫЙ_ЛОГИН","credential":"ВРЕМЕННЫЙ_ПАРОЛЬ"}]'
  npm run start:server
  ```

  Используйте ограниченные по времени TURN-учётные данные: конфигурация передаётся подключённым клиентам, поэтому постоянные секреты провайдера хранить в ней нельзя. Без доступного TURN-сервера голосовая связь всё ещё может не работать в сетях, запрещающих прямые P2P-соединения.
- **Режимы микрофона:**
  - Постоянная активация по голосу (Voice Activity Detection с визуализатором громкости).
  - Push-To-Talk (удержание клавиши `Пробел` на ПК или сенсорная кнопка на смартфонах).
- **Безопасность:** микрофон освобождается и аудиодорожки выключаются при выходе из комнаты.

## 3. Хранение истории чата на стороне хоста

История сообщений сохраняется на компьютере хоста в пользовательской системной папке:
- **Windows:** `%USERPROFILE%\.spyverse\rooms\<ROOM-ID>\chat\history.json`
- **Linux/macOS:** `~/.spyverse/rooms/<ROOM-ID>/chat/history.json`

Идентификаторы комнат фильтруются для предотвращения Path Traversal атак (разрешены только алфавитно-цифровые символы).
